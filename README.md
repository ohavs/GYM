# מסלול (Maslul)

אפליקציית אימונים בעברית, mobile first, שנבנתה סביב מאגר
[exercises-dataset](https://github.com/hasaneyldrm/exercises-dataset) של 1,324 תרגילים.

האפליקציה משרתת שני תפקידים באותה מערכת: **מתאמן** שמקבל מסלול שנבנה לפי המטרה,
הניסיון והציוד שלו, ו**מאמן** שמנהל מתאמנים ובונה להם תוכניות מאותו מאגר.

---

## מה יש כאן

| מסך | תיאור |
|---|---|
| הרשמה (`/welcome`) | שישה שלבים: שם, מטרה, ניסיון, תדירות, ציוד, דגשים. בסיום נבנה מסלול. |
| בית (`/`) | האימון הבא, טבעת יעד שבועי, רצף, נפח, היסטוריה אחרונה. |
| מסלול (`/program`) | שבוע האימונים המלא, נפח שבועי לפי אזור, פתיחת יום והתחלת אימון. |
| תרגילים (`/library`) | חיפוש וסינון על כל 1,324 התרגילים, גלילה אינסופית, שמירת מועדפים. |
| אימון (`/workout`) | נגן אימון: רישום סטים, טיימר מנוחה, החלפת תרגיל, סיכום. |
| התקדמות (`/progress`) | נפח שבועי, שיאים אישיים, היסטוריה מלאה. |
| מאמנים (`/coach`) | רשימת מתאמנים לפי דחיפות, ועורך מסלול מלא לכל מתאמן. |
| פרופיל (`/profile`) | הגדרות אימון, חשבון וסנכרון, מצב מאמן, נתונים. |

## Firebase

האפליקציה עובדת גם בלי חשבון: במצב אורח הכל נשמר ב-`localStorage`. חיבור לחשבון
גוגל מוסיף סנכרון בין מכשירים והגנה מפני ניקוי הדפדפן.

### הגדרה

מפתחות הפרויקט יושבים ב-`.env`. הם ציבוריים בכוונה: Google מגדירה את מפתח ה-Web API
כמזהה ולא כסוד. ההגנה מגיעה מכללי Firestore ומרשימת הדומיינים המורשים בקונסולה.

לפני העלייה לאוויר:

1. **Authentication → Settings → Authorized domains** — הוסיפו את הדומיין שלכם.
2. **Firestore rules** — הפעילו את הכללים שבריפו:
   ```bash
   firebase deploy --only firestore:rules
   ```

### למה Firestore ולא Realtime Database

הנתונים כאן מובנים ודורשים שאילתות: "האימונים של המשתמש מהחודש האחרון", "המתאמנים
של המאמן הזה". RTDB הוא עץ JSON אחד עם שאילתות חלשות, והוא מנצח רק בסנכרון בתדירות
גבוהה מאוד. בנוסף Firestore מביא offline persistence מובנה, שקריטי לאפליקציה שרצה
בחדר כושר עם קליטה גרועה.

### מבנה הנתונים

```
users/{uid}                  פרופיל, מסלול, תרגילים שמורים, משקלים אחרונים
users/{uid}/logs/{logId}     מסמך לכל אימון שהושלם
users/{uid}/trainees/{id}    רשימת המתאמנים של מאמן, כל אחד עם המסלול שלו
```

יומנים ומתאמנים הם תת-אוספים ולא מערכים על מסמך המשתמש, כך שהיסטוריה ארוכה לא
מתקרבת למגבלת ה-1MB למסמך וניתן יהיה לדפדף בה בהמשך בלי לשנות את המבנה.

הסנכרון (`src/lib/sync.ts`) מושך מהענן בכניסה וכותב בחזרה בהשהיה של שנייה. בהתחברות
ראשונה החשבון מאמץ את מה שכבר נבנה במצב אורח, כך שאף אחד לא מאבד מסלול בגלל שיצר חשבון.

## הנתונים

הריפו כבר כולל את הנתונים המוכנים ב-`public/data/`. כדי לבנות אותם מחדש מהמקור:

```bash
git clone --depth 1 https://github.com/hasaneyldrm/exercises-dataset /tmp/exercises-dataset
node scripts/build-dataset.mjs /tmp/exercises-dataset
```

הסקריפט מייצר שלושה קבצים:

| קובץ | גודל | מתי נטען |
|---|---|---|
| `public/data/exercises.json` | 352 KB | פעם אחת בעליית האפליקציה |
| `public/data/steps.json` | 625 KB | רק כשנפתח דף תרגיל |
| `public/data/meta.json` | 19 KB | עם האינדקס |

### התרגום לעברית

המאגר המקורי מגיע בעשר שפות, אף אחת מהן אינה עברית. שכבת התרגום נמצאת ב-
`scripts/hebrew-lexicon.mjs`:

- **טקסונומיה** (אזורי גוף, ציוד, שרירים) מתורגמת במלואה, ידנית.
- **שמות התרגילים** נבנים מחדש בדקדוק עברי ולא מתורגמים מילה במילה. המנוע מזהה
  את תנועת הליבה, התנוחה, האחיזה והצדדיות, ומרכיב שם תקין: `barbell seated
  close grip row` הופך ל"חתירה בישיבה במוט אחיזה צרה". כיסוי: 1,324 מתוך 1,324.
- **הוראות ביצוע** נכתבו לפי דפוס תנועה (40 דפוסים, כל אחד עם דגשי ביצוע בעברית).
  ההוראות המקוריות באנגלית זמינות בכל דף תרגיל תחת אקורדיון.

להוראות מתורגמות פר-תרגיל (7,710 משפטים) אפשר להריץ מעבר LLM על `steps.json`
ולהזרים את התוצאה חזרה לאותו מבנה. הממשק כבר תומך בזה: `ExerciseSheet` קורא
מ-`steps.json` לפי מזהה תרגיל.

## מדיה ורישוי

זו הנקודה שדורשת החלטה לפני מסחור.

- **הנתונים** (שמות, קטגוריות, שרירים, הוראות) הם MIT. מותר לשימוש מסחרי.
- **המדיה** (התמונות והגיפים) היא רכושה של [Gym visual](https://gymvisual.com/),
  מופצת במאגר המקורי ברשות נפרדת. `NOTICE.md` שם אומר במפורש: *"cloning this repo
  is not a license"*. לשימוש מסחרי צריך רישיון ישיר מ-Gym visual, או מדיה חלופית.

הארכיטקטורה מוכנה להחלפה:

- **תמונות ממוזערות** (1,324 קבצים, 12MB) יושבות ב-`public/media/img/`.
- **הנפשות** נטענות מ-CDN חיצוני שניתן להחלפה במשתנה סביבה אחד:

```bash
NEXT_PUBLIC_MEDIA_CDN=https://cdn.example.com/exercises
```

הנתיב הצפוי הוא `{CDN}/videos/{mediaId}.gif`. אם ה-CDN לא זמין, הכרטיס נשאר עם
התמונה הסטטית ולא נשבר. ייחוס Gym visual מוצג בדף כל תרגיל ובמסך הפרופיל.

## ארכיטקטורה

```
src/
  app/
    (tabs)/         מסכים עם סרגל תחתון
    welcome/        הרשמה
    workout/        נגן אימון במסך מלא
  components/
    ui/             רכיבי בסיס: כפתור, שיט, טוסט, שדות, סטפר, טבעת התקדמות
    layout/         מעטפת מסך, סרגל ניווט, שער טעינה
    exercise/       מדיה, כרטיס, דף תרגיל
    workout/        טיימר מנוחה, סיכום אימון
    coach/          בורר תרגילים
  lib/
    data.ts         טעינת מאגר, חיפוש, סינון
    program.ts      מחולל התוכניות
    store.ts        מצב מקומי (zustand + localStorage)
    firebase.ts     אתחול, כניסה עם גוגל
    sync.ts         סנכרון דו-כיווני מול Firestore
    session.ts      חישובי אימון, רצף, שיאים
    clock.ts        קריאת שעון דרך useSyncExternalStore
firestore.rules      כללי גישה: כל משתמש רואה רק את התת-עץ שלו
scripts/
  hebrew-lexicon.mjs   מילון ודקדוק לשמות בעברית
  build-dataset.mjs    בניית הנתונים מהמאגר המקורי
```

**סטאק:** Next.js 16 (App Router), React 19, Tailwind v4, Motion, Zustand,
Phosphor Icons, Firebase (Auth + Firestore).

### מחולל התוכניות

`src/lib/program.ts` מחזיק תבניות ימים (גוף מלא, עליון/תחתון, דחיפה/משיכה/רגליים)
ומרשם סטים וחזרות לפי מטרה. לכל משבצת בתבנית הוא בוחר את התרגיל המדורג הגבוה
ביותר שתואם לדפוס התנועה, לציוד הזמין ולרמת המתאמן, בלי לחזור על תרגיל באותו שבוע.
דירוג התרגילים (`rank`) מחושב בזמן בניית הנתונים ומעדיף תרגילי יסוד על וריאציות נדירות.

## עיצוב

שפת העיצוב: קנבס בהיר ורך, כרטיסים לבנים, משטחי פסטל, ודיו כמעט-שחור לכל פעולה
ראשית. אלמנטים גדולים, פינות נדיבות, וצללים כמעט בלתי נראים.

- **RTL מלא** עם תכונות לוגיות (`ps/pe/ms/me/start/end`); אייקונים כיווניים מתהפכים,
  וגרף הנפח מתקדם מימין לשמאל כמו שאר הדף.
- **צבע כמשמעות ולא כקישוט**: הפסטלים הם משטחים (אפרסק, מנטה, לילך, חמאה, שמיים,
  ורוד), ההדגשה היחידה היא הדיו. ירוק, ענבר ואדום שמורים למצב סמנטי בלבד.
- **סקאלת פינות אחת**: פיל לכל פקד, 28px למכולות, 22px לשדות ולמדיה.
- **טיפוגרפיה**: Rubik במשקלים 300 עד 700. אין פונט מונו, המספרים חיים באותה משפחה
  עם `tabular-nums` כדי שטיימר לא ירעיד את שכניו.
- **תנועה**: Motion בלבד. כניסה מדורגת לכל מסך, קפיץ על כל נגיעה, גרף שמצייר את עצמו,
  ומספרים שמתגלגלים. `prefers-reduced-motion` מכובד בכל מקום.
- כל שדה, מתג, בורר, סטפר והתראה מעוצבים. אין אלמנט דפדפן בברירת מחדל.
- **הדגמות התרגילים הן הוויזואליה**: הן יושבות ישירות על משטח צבעוני עם
  `mix-blend-mode: multiply`, כך שהרקע הלבן של המקור נעלם והדמות נקראת כגזירה על הכרטיס.
